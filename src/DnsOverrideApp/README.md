# DNS Override

Подменяет ответы на домены из скомпилированного файла правил.

Приложение читает **один файл** — `/etc/dns-override/ruleset.dat`. Правила в нём
окончательные: их собирает, дедуплицирует и разрешает конфликты Telegram-бот.
Приложение находит самое длинное совпадение по суффиксу домена и формирует ответ;
домен, не попавший ни под одно правило, резолвится штатно.

## Конфигурация приложения

```json
{
  "rulesetPath": "/etc/dns-override/ruleset.dat",
  "runtimeStatePath": "/etc/dns-override/runtime-state.json",
  "enabled": true,
  "appPreference": 20,
  "watch": {
    "debounceMs": 500,
    "pollIntervalSec": 60
  }
}
```

| Поле | Назначение |
|---|---|
| `rulesetPath` | файл правил; пишет его бот, приложение только читает |
| `runtimeStatePath` | обратный канал: приложение пишет сюда состояние и счётчики |
| `enabled` | `false` — аварийный тумблер: все запросы уходят на обычный резолв |
| `appPreference` | порядок среди установленных приложений; меньше — раньше (по умолчанию у приложений без этого поля — 100) |
| `watch.debounceMs` | пауза после последнего события файловой системы перед перезагрузкой |
| `watch.pollIntervalSec` | страховочный `stat` файла — на случай, если inotify не работает (bind-mount, NFS, SMB) |

Targets, `qtypePolicy`, `defaultAction` и аварийный тумблер движка лежат
в заголовке самого `ruleset.dat` — второго источника настроек нет.

## Состояние

`runtime-state.json` перезаписывается после каждой загрузки правил и раз в
`pollIntervalSec`: версия приложения, применённая `revision`, число правил,
время и длительность последней загрузки, последние ошибки и счётчики запросов.

## Сброс кэша

Приложение кэш DNS-сервера **не сбрасывает**: интерфейс приложений Technitium
(`IDnsServer`, `IDnsCache`) операции сброса не предоставляет. Автоматически кэш
не сбрасывается вообще — это делает оператор кнопкой в боте
(«🧰 Сервис → 🧹 Сбросить весь кэш DNS»), и всегда целиком.
