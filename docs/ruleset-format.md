# Формат `ruleset.dat` — контракт между ботом и приложением

Единственный файл, который читает приложение. Пишет его только бот (в будущем — web-ui).
Правила в нём **окончательные**: уже собраны, объединены, дедуплицированы и разрешены
по приоритетам. Приложение не знает ни об источниках, ни о приоритетах, ни о том,
пришло правило от пользователя или из списка.

Файл машинный. Читаемость для человека не требуется — вся работа идёт через бота.

Путь по умолчанию: `/etc/dns-override/ruleset.dat`, переопределяется в `dnsApp.config`.

---

## 1. Общая структура

```
!DNSOVR1 {заголовок в одну строку JSON}\n
WO0 com.google\n
WP0 com.google.test\n
AO1 org.example\n
```

- Кодировка UTF-8 без BOM, переводы строк — `\n` (LF).
- **Строка 1** — сигнатура `!DNSOVR1`, один пробел, JSON-объект заголовка в одну строку.
- **Строки 2..N** — тело: по одному правилу в строке.
- Файл заканчивается `\n`. Пустых строк и комментариев в теле нет.

Сигнатура: `!DNSOVR` + номер версии формата. Приложение отказывается грузить файл
с неизвестной сигнатурой — молча интерпретировать чужой формат нельзя.

## 2. Заголовок

```json
{
  "version": 1,
  "revision": 128,
  "generatedAt": "2026-08-09T12:34:56Z",
  "generator": "dns-override-bot/0.4.1",
  "count": 312455,
  "sha256": "e3b0c44298fc1c149afbf4c8996fb92427ae41e4649b934ca495991b7852b855",
  "engine": {
    "enabled": true,
    "defaultAction": "passthru",
    "defaultTarget": null,
    "logMatches": false,
    "logSampleRate": 0.0
  },
  "targets": [
    { "name": "default",   "mode": "address", "ipv4": ["10.8.0.1"], "ipv6": [], "ttl": 60, "rotation": "none", "emptyFamilyPolicy": "nodata" },
    { "name": "proxy-nl",  "mode": "address", "ipv4": ["10.8.0.2"], "ipv6": ["fd00:dead:beef::2"], "ttl": 60, "rotation": "round-robin", "emptyFamilyPolicy": "nodata" },
    { "name": "blackhole", "mode": "nxdomain", "ttl": 300 }
  ],
  "qtypePolicy": { "A": "target", "AAAA": "target", "HTTPS": "nodata", "SVCB": "nodata", "ANY": "nodata", "*": "passthru" }
}
```

| Поле | Обяз. | Назначение |
|---|---|---|
| `version` | да | `1` для обычных правил, `2` для файла с `policy` |
| `revision` | да | монотонный счётчик сборок. Бот сверяет его с `appliedRevision` в `runtime-state.json` |
| `generatedAt` | да | ISO-8601 UTC |
| `generator` | нет | имя и версия писателя — для диагностики |
| `count` | да | число строк в теле. Не совпало с фактическим — файл отвергается |
| `sha256` | да | hex, нижний регистр, sha256 **тела** (всё после первого `\n`, включая последний `\n`) |
| `engine` | да | глобальные настройки движка |
| `targets` | да | массив; правило ссылается на элемент **по индексу** |
| `qtypePolicy` | да | карта «тип записи → действие» |
| `policy` | при `version=2` | белые списки доменов и IP-сетей, шаблоны GeoSite |

`engine.enabled: false` — аварийный полный passthru: приложение грузит файл,
но на все запросы возвращает `null`.

`engine.defaultAction` — что делать с доменом, не попавшим ни под одно правило.
По умолчанию `passthru`. При `override` обязателен `defaultTarget` (имя из `targets`).

Полей сброса кэша (`flushCacheOnReload`, `flushScope`) в заголовке **нет**: кэш
DNS-сервера сбрасывается только вручную кнопкой в боте и только целиком, см.
[`ruleset-loading.md §7`](ruleset-loading.md#7-сброс-кэша-dns-делается-вручную-из-бота).
Файлы, собранные ранними версиями бота, эти поля ещё содержат — приложение их
игнорирует наравне с любыми другими неизвестными полями (§6).

### `targets[]`

| Поле | Обяз. | По умолчанию | Назначение |
|---|---|---|---|
| `name` | да | — | только для логов и `runtime-state.json`; связь идёт по индексу |
| `mode` | да | — | `address` \| `nxdomain` \| `nodata` \| `refused` |
| `ipv4` | при `address` | `[]` | адреса для `A` |
| `ipv6` | при `address` | `[]` | адреса для `AAAA` |
| `ttl` | нет | `60` | TTL в ответе, секунды |
| `rotation` | нет | `none` | `none` \| `round-robin` \| `random` |
| `emptyFamilyPolicy` | нет | `nodata` | запрошено семейство, для которого адресов нет |

При `mode: address` обязателен непустой `ipv4` **или** `ipv6`.
Максимум 256 targets (индекс влезает в `byte`… ограничение мягкое, но фиксируем).

Схема заголовка для валидации: [`schema/ruleset-header.schema.json`](schema/ruleset-header.schema.json).

### `policy` в версии 2

- `allowDomains` содержит нормализованные домены. Простой домен включает поддомены, `@example.org` включает только само имя.
- `allowNetworks` содержит IPv4/IPv6 в CIDR. Бот объединяет пересекающиеся диапазоны перед записью.
- `patterns` содержит объекты с `kind` (`substring` или `regexp`), `value`, `action` (`override`, `passthru` или `allowlist`) и `targetIndex`. Для `passthru` и `allowlist` индекс равен `0`. Бот задаёт порядок обычных шаблонов по приоритету источника и правилу конфликтов.
- `protectedZones` содержит суффиксы, где обычные шаблоны пропускаются. Белые списки действуют и в этих зонах.

В версии 2 сигнатура, тело, `count` и `sha256` сохраняют прежний формат. Установите
приложение `v0.4` до первого применения белых списков или шаблонов GeoSite.

## 3. Тело: строка правила

```
<scope><action><targetIndex><SP><rdomain>
```

Пример: `WO0 com.google` — wildcard, override, target[0], домен `google.com`.

| Позиция | Значение |
|---|---|
| байт 0 | `W` — wildcard (домен + поддомены любой глубины) / `A` — apex (только сам домен) |
| байт 1 | `O` — override (ответить по target) / `P` — passthru (не подменять) |
| байт 2… | индекс в `targets[]`, десятичное число без ведущих нулей. При `P` — всегда `0`, приложением игнорируется |
| далее | один пробел `0x20` |
| далее | `rdomain` до конца строки |

`rdomain` — домен с **метками в обратном порядке**, соединёнными точкой:

```
test.google.com   →  com.google.test
сайт.рф           →  xn--p1ai.xn--80aswg
```

Домен уже нормализован ботом: нижний регистр, punycode (UTS-46 / IDNA2008),
без завершающей точки, только `[a-z0-9.-]`. Приложение нормализацию **не делает** —
оно лишь приводит QNAME входящего запроса к нижнему регистру и отбрасывает
завершающую точку. Преобразование в punycode на этом этапе не нужно: имена в
DNS-пакете приходят уже в ASCII (`DnsDatagram` декодирует метки через
`Encoding.ASCII`), а IDN клиент кодирует до отправки запроса.

Ограничения строки: длина ≤ 512 байт, `rdomain` ≤ 253 байта, метка ≤ 63 байта.

### Порядок и уникальность

1. Тело отсортировано по `rdomain` **побайтово по возрастанию** (ordinal).
   В Python — обычная сортировка `str` для ASCII, в C# — `StringComparer.Ordinal`
   или сравнение `ReadOnlySpan<byte>`.
2. При одинаковом `rdomain` строка со `scope = A` идёт **перед** `W`.
3. Пара (`rdomain`, `scope`) уникальна: не более одной строки.

Сортировка — часть контракта, а не оптимизация: приложение делает бинарный поиск
прямо по файлу, загруженному в память, и не строит дерево.

## 4. Что обязан гарантировать бот

| # | Гарантия | Почему |
|---|---|---|
| G1 | Правила окончательные: конфликты между источниками и пользователем уже разрешены | приложение не знает о приоритетах |
| G2 | Не более одной строки на (`rdomain`, `scope`) | иначе поведение неопределено |
| G3 | Тело отсортировано по правилам §3 | бинарный поиск |
| G4 | `count` и `sha256` соответствуют телу | защита от обрезанного файла |
| G5 | Все `targetIndex` существуют в `targets[]` | приложение не чинит битые ссылки |
| G6 | Домены нормализованы | иначе правило молча не сработает |
| G7 | Запись атомарна: `.tmp` → `fsync` → `rename()` | приложение не должно увидеть полуфайл |

Чего бот сделать **не может** — схлопнуть иерархию: wildcard покрывает бесконечное
множество поддоменов. Поэтому разбор по длине суффикса остаётся в приложении
(см. [`rule-matching.md`](rule-matching.md)).

## 5. Пример

[`config-examples/ruleset.dat`](../config-examples/ruleset.dat) — рабочий файл,
проходящий проверку `tools/check-ruleset.py`.

Проверить свой файл:

```bash
python3 tools/check-ruleset.py /etc/dns-override/ruleset.dat
```

Проверяются: сигнатура, схема заголовка, `count`, `sha256`, порядок сортировки,
дубликаты, диапазон `targetIndex`, формат доменов.

## 6. Версионирование

- `!DNSOVR<N>` меняется при несовместимом изменении **тела** (раскладка строки, сортировка).
- `version` в заголовке — при изменениях внутри заголовка.
- Неизвестные поля заголовка приложение игнорирует; это позволяет боту новее приложения
  добавлять поля без поломки.
- Приложение с неизвестной сигнатурой или `version` больше поддерживаемой отказывается
  грузить файл, оставляет прошлый снапшот и пишет ошибку в `runtime-state.json`.
